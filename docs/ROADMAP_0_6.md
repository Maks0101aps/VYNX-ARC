# План VYNX ARC 0.6.0

Status: 0.6.0 implemented; see [acceptance report](MILESTONE_0_6.md) and
[verification identities](VERIFICATION_0_6.json). This tracker retains the original
plan. Checked items refer to the report's explicit scope, not universal qualification.
Unchecked items identify remaining partial work: internal phase profiling, complete
GUI dispatch typing, a full manual keyboard matrix and trusted Explorer registration.
База: `v0.5.0`, коммит `be1befc`.

## Цель

Сделать ежедневные операции быстрыми и предсказуемыми: извлечь несколько файлов из
большого архива, перепаковать архив в другой формат, безопасно сохранить правки и
разобраться с результатом прерванной работы. Версия сохраняет офлайн-режим и текущие
форматы, шифрование, вкладки и защиту путей.

Основания: [статус 0.5](IMPLEMENTATION_STATUS.md), [отчёт](MILESTONE_0_5.md),
[замеры](BENCHMARKS_0_5.md). Числа ниже взяты из сохранённого отчёта 0.5, а не из
нового запуска тестов. Фактические результаты 0.6 приведены в [новом отчёте](BENCHMARKS_0_6.md):
выборочное извлечение — 1,78 с в ядре / 3,32 с в GUI; поиск GUI p95 — 36,6 мс.
Холодный запуск процесса отделён от повторных операций; кеш ОС не сбрасывался.

## 1. Быстрые операции на больших архивах — P0

Проблема: в 0.5 выборочное извлечение одного файла из ZIP со 100 тысячами записей
занимает около 40 секунд; выбранный просмотр — около 0,92 с. Поиск уже укладывается
в p95 около 63 мс на синтетической модели, и этот результат нужно сохранить.

- [x] Разделить проверку полного набора метаданных и подготовку реально выбранных
  выходных путей. Не выполнять файловые проверки назначения для невыбранных файлов.
- [ ] Профилировать открытие, валидацию, подготовку назначения, декодирование и
  публикацию раздельно; сохранить повторяемый набор 0.5 для сравнения.
- [x] Переиспользовать безопасный индекс открытого архива для повторного просмотра
  и навигации. При изменении источника сбрасывать индекс; размер/mtime не считать
  криптографическим доказательством неизменности при записи.
- [x] Сохранять полную проверку опасных имён, коллизий, размеров и ограничений до
  вывода. Ускорение не достигается отключением проверок безопасности.
- [x] Проверить память и дескрипторы на 100 циклах, включая извлечение, реальные
  переключения вкладок и закрытие документов, а не только модель или отдельные CLI.

**Приёмка:** цель выборочного извлечения на том же 100k ZIP и хосте — медиана до
5 секунд вместо примерно 40. Поиск p95 не выше 100 мс на прежней синтетической
модели, дополнительно замеряется полный GUI с реальным архивом. Для тёплого
выборочного просмотра задать и зафиксировать цель после профилирования этапа 1.
Медианы минимум трёх запусков; изменения времени >10% или RSS >15% расследуются.
Холодные и повторные операции измеряются отдельно; не выбирать только лучший прогон.

## 2. Контролируемое выполнение архивных операций — P0

Проблема: ограничения распакованных байтов не ограничивают все выделения библиотек
при разборе метаданных. Сбой нативного декодера не должен закрывать всё приложение.

- [x] Ввести принадлежащий проекту рабочий процесс для разбора архивов и выполнения
  операций. Сначала перенести открытие/просмотр/тестирование; запись переносить после
  реализации протокола восстановления из направления 3.
- [x] Ограничить память, время выполнения и количество фоновых операций профилями
  ресурсов. Значения назначить по реальным пикам и совместимости, а не произвольно.
- [x] Версионировать протокол, ограничить размер сообщений и метаданных, обрабатывать
  повреждённые сообщения, зависание, обрыв связи и завершение процесса.
- [x] Передавать пароли только через контролируемый канал в памяти. Исключить их из
  аргументов процесса, окружения, журналов и диагностических дампов приложения.
  Полное исключение секретов из системных дампов не обещается без отдельной проверки.
- [x] Показать понятные состояния: превышен лимит, источник повреждён, процесс
  остановлен, результат требует проверки. Другие вкладки остаются доступны.
- [x] Добавить длительные кампании повреждённых входов и доступные инструментированные
  сборки; сохранять минимизированные воспроизводимые случаи в регрессионном наборе.

**Приёмка:** намеренный crash, превышение памяти и зависание рабочего процесса
не завершают GUI и не теряют рабочие копии. Ограничения реально срабатывают на
контрольных входах. Перед кандидатом провести не менее 4 часов совокупного fuzzing
с отчётом по путям ZIP/7Z/RAR/TAR/streams, бюджету и охвату; не оставлять
неразобранных сбоев. Исчерпание заданного лимита отличать от дефекта парсера.

Изоляция процесса ограничивает последствия сбоя и потребление ресурсов. Она сама
по себе не является отдельной границей файловых прав или полной песочницей.

## 3. Очередь без неоднозначных результатов — P0

- [ ] Ввести единый типизированный путь запуска: проверка параметров, владение

  диспетчеризации от произвольных замыканий и состояния активной вкладки.
- [x] Полностью сохранять большие выделения в ограниченном проверяемом хранилище
  описаний. Версионировать и мигрировать журнал 0.5; не терять записи при ошибке
  миграции и не обрезать запросы незаметно.
- [x] Различать: ожидает, выполняется, требует решения, проверяется после сбоя,
  завершено, ошибка, отменено. Неизвестный результат публикации не выдавать ни за
  успех, ни за гарантированное отсутствие изменений.
- [x] Определить протокол намерения публикации и сверки фактического результата
  после завершения процесса. Проверять содержимое/идентичность результата перед
  признанием работы завершённой; не повторять запись автоматически.
- [x] Добавить «Повторить только неудачные» для пакета, понятные счётчики, фильтры

- [x] Показывать нехватку места до записи и ошибки финальной публикации отдельно.
  Оценка свободного места не называется резервированием диска.

**Приёмка:** остановить процесс до, во время и после пересборки и вокруг точки
публикации; после запуска получить корректное состояние, доступную правку и явное
следующее действие. Проверить смену источника/назначения, повреждённый журнал,
недоступный диск и большие выделения. Записи в один архив остаются последовательными.
Побайтовое продолжение декодирования после перезапуска не входит в обещания версии.

## 4. Конвертация и пакетная перепаковка — P1, обязательная функция

Основной новый пользовательский сценарий версии: `RAR/TAR/ZIP/7Z → ZIP/7Z`
для уже поддерживаемых читаемых вариантов, с понятными настройками результата.

- [x] Конвертировать один архив или пакет через очередь: формат, сжатие, ресурсы,
  выходной каталог, шифрование результата и правила конфликта имён.
- [x] Перед запуском показать план: входы, назначения, сохранение/потеря
  поддерживаемых метаданных, ограничения и потребность во временном месте.
- [x] Переносить проверяемые потоки через ядро без запуска сторонних архиваторов.
  Временное хранение, если необходимо конкретному пути, ограничить и обозначить.
- [x] По умолчанию создавать новый архив и сохранять исходник. Проверять итоговый
  контейнер и содержимое до публикации; не сообщать успех при частичном результате.
- [x] Явно выбирать шифрование назначения. Не снимать его молча при конвертации
  зашифрованного источника; не хранить введённые пароли в заданиях на диске.
- [x] Поддержать отмену, повреждённый вход, занятый выход и недостаток места.
  Неподдерживаемые комбинации объяснять до записи.

**Приёмка:** независимые читатели подтверждают набор имён и хеши файлов результата
для обычных/зашифрованных ZIP/7Z и читаемых RAR/TAR. Исходник остаётся неизменным.
Пакет из успешных и ошибочных входов имеет корректный итог; повторяются только
выбранные неудачные задачи. Создание RAR не добавляется.

## Порядок реализации

| Этап | Рабочий результат |
| --- | --- |
| 1 | База 0.5, профилирование медленного извлечения, сценарии приёмки и протокол заданий |
| 2 | Рабочий процесс для чтения, лимиты и корректный отказ; GUI переживает его остановку |
| 3 | Быстрое выборочное извлечение и проверка настоящего GUI на больших архивах |
| 4 | Устойчивый журнал и сверка публикации; перенос записи в рабочий процесс |
| 5 | Конвертация/перепаковка и сохранение правок в новый архив |
| 6 | Реальные редакторы, интерфейс, локализация, пакеты и итоговая регрессия |

Каждый этап заканчивается работающим сценарием и собственной проверкой. Изменения
проверяются до следующего большого слоя. Исправленные сбои становятся регрессионными
тестами. Переход на 0.6.0 в метаданных — при подготовке кандидата, а не при записи плана.

## Что оставить вне обязательного объёма

Облако, аккаунты, телеметрию, AI, создание RAR, массовое добавление новых форматов,
встроенный Office/браузер, автоматическое слияние правок, сетевой автообновлятор,
неограниченную параллельную запись и побайтовое восстановление декодеров.

Вложенные архивы и перенос элементов между архивами — кандидаты следующей версии:
сначала завершаются конвертация и надёжная фиксация результатов. Подпись готовится
отдельно при наличии сертификата и инфраструктуры доверия; наличие подписи не
подменяет испытания и не обещает отсутствие предупреждений SmartScreen.
