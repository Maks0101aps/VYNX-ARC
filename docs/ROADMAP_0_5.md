# План VYNX ARC 0.5.0

Статус: реализованная development-веха 0.5.0. Проверки и границы квалификации
зафиксированы в [MILESTONE_0_5.md](MILESTONE_0_5.md).
База: `v0.4.0`, коммит `f8a9353`.

## Цель версии

Сделать VYNX ARC удобным основным архиватором для ежедневной работы:
пользователь держит несколько архивов открытыми, управляет заданиями,
возвращается к незавершённой работе и явно сохраняет изменения файлов в архив.
Быстродействие, сохранность данных и понятные решения пользователя входят в
критерии готовности каждой функции.

Основные сценарии: проекты с большим количеством файлов, архивы документов,
пакетная распаковка и правка отдельных файлов внутри ZIP/7Z. Форматы и защита,
которые работают в 0.4, должны сохраняться.

## Что подтверждено в 0.4 и чего не хватает

| Основание | Следствие для 0.5 |
| --- | --- |
| Одна текущая модель/путь/пароль в MainWindow; при работе страницы блокируются | Вынести состояние архива и владение заданиями; затем добавить вкладки |
| OperationQueue хранит функции-замыкания только в памяти | Для восстановления нужны описания заданий и явные состояния |
| Внешнее открытие создаёт копию только для чтения без сохранения обратно | Редактирование требует отдельного сценария, контроля конфликтов и транзакционной замены |
| preview::bytes использует общий обход streams | Измерить чтение выбранного файла; добавить выборочный путь для подходящих форматов |
| Настройки создания не управляют пересборкой при изменении ZIP/7Z | Уточнить и реализовать настройки пересборки и сохранение метаданных |
| Временные копии очищаются при запуске по возрасту | Нужны видимое управление копиями, счётчик места и защита несохранённых правок |
| Есть локальные тесты и пакетная проверка; старые документы описывают разные этапы | Сохранить проверку готовых пакетов и привести актуальную документацию к одной версии |

Основания: [0.4](MILESTONE_0_4.md), [статус](IMPLEMENTATION_STATUS.md),
[изменение архивов](MODIFICATION.md), [модель защиты](SECURITY_MODEL.md).
Исторические измерения производительности не считаются замерами 0.5.

## Обязательный объём

### A. Рабочее пространство с вкладками — P0

- [x] Вынести состояние открытого архива в ArchiveSession: путь, модель,
  навигация, поиск, выделение, пароль в памяти, признак занятости/изменения.
- [x] Вынести запуск и завершение операций из MainWindow в отдельный контроллер.
  Каждое задание знает свою сессию и захваченные параметры.
- [x] Добавить вкладки: открыть несколько архивов, переключить, закрыть,
  Ctrl+Tab, Ctrl+Shift+Tab и Ctrl+W. Повторное открытие уже открытого архива
  активирует его вкладку; тома одного архива приводятся к одной идентичности.
- [x] Сохранять папку, поиск и выделение каждой вкладки. Незанятые вкладки
  доступны, пока выполняется задание другой вкладки.
- [x] При закрытии занятой вкладки предложить дождаться/отменить операцию.
  Результат операции не должен попадать в другую активную вкладку.
- [x] Предлагать восстановить список вкладок после запуска. Пароли не сохранять;
  конфиденциальные пути включать в сессию только при разрешённой истории.

**Готово, когда:** три архива открыты одновременно; во время извлечения из
первого можно искать и просматривать второй; закрытие/переключение вкладок
не смешивает модели, пароли, результаты и сообщения об ошибках. Это проверено
реальными асинхронными сценариями, включая зашифрованные архивы и тома.

### B. Очередь с восстановлением и повтором — P0

- [x] Заменить хранение только функций типизированными описаниями заданий:
  операция, источники, назначение, выбранные элементы, настройки и идентичность
  исходного архива. Пароли и содержимое файлов в журнал не записывать.
- [x] Ввести состояния: ожидает, выполняется, требует решения, завершено,
  ошибка, отменено, прервано перезапуском. Различать паузу очереди и отмену работы.
- [x] Атомарно сохранять ограниченный журнал, версию схемы и настройки очереди.
  При отключённой истории не сохранять чувствительные пути на диск.
- [x] После аварийного завершения отмечать активное задание как прерванное.
  Восстановленные задания запускать только после явного действия пользователя.
- [x] Добавить «Повторить» и «Изменить и повторить» для подходящих заданий:
  повторная проверка источника, свободного места и конфликтов; новый запрос
  пароля. Повтор создаёт новое задание и сохраняет исходную ошибку.
- [x] Добавить итог пакетной обработки: успешно/ошибки/отменено, открыть папку
  результата и экспортировать отчёт. Очистка истории доступна пользователю.

**Готово, когда:** принудительный останов приложения не создаёт ложных успехов;
после запуска очередь восстанавливается без автоматического повторения записи.
Изменённый/удалённый источник требует решения. На диске нет паролей. Нельзя
выполнить две записи в один архив одновременно. Базовый планировщик остаётся
последовательным; доступность вкладок не означает неограниченную параллельность.

### C. «Редактировать и сохранить в архив» для ZIP/7Z — P0

- [x] Сохранить действие «Открыть» только для чтения. Добавить отдельное
  «Редактировать копию» для ограниченного списка поддерживаемых файлов.
- [x] Создавать отдельную рабочую копию и записывать идентичность исходного
  архива/элемента, исходный хеш, имя элемента и настройки шифрования.
- [x] Отслеживать изменение файла. После стабилизации записи показывать
  «Сохранить в архив», «Сохранить как…» и «Отбросить». Закрытие внешнего
  приложения само по себе не считается подтверждением сохранения.
- [x] Добавить в ядро транзакционную замену содержимого выбранного элемента:
  пересборка, проверка, публикация, затем обновление нужной вкладки.
- [x] Если архив или элемент изменился с момента открытия, остановить запись
  и предложить перечитать исходник либо экспортировать правку. Без скрытого
  перезаписывания и автоматического слияния.
- [x] Сохранять шифрование, поддерживаемые метаданные и выбранные настройки
  пересборки. Для неподдерживаемых комбинаций явно объяснять ограничение.
- [x] Обработать занятый файл, неполную запись редактором, нехватку места,
  отмену и ошибку публикации. Рабочую копию с несохранённой правкой не удалять
  обычной очисткой временных файлов.
- [x] При закрытии VYNX показывать несохранённые правки. После перезапуска
  предлагать восстановление зарегистрированных рабочих копий без хранения
  паролей; объяснять, что расшифрованное содержимое остаётся на диске.

**Готово, когда:** текст изменяется во внешнем редакторе и после явного сохранения
читается из ZIP/7Z независимым читателем, включая зашифрованные варианты.
При конфликте исходника, отмене, блокировке, нехватке места и падении приложения
исходный архив остаётся пригодным, а несохранённую правку можно восстановить
или экспортировать. Исполняемые файлы/скрипты не запускаются автоматически.

### D. Большие архивы и измеримая скорость — P0

- [x] Снять воспроизводимую базу 0.4 на той же машине: открытие, поиск,
  предпросмотр, тестирование, извлечение, изменение, отмена, CPU и пиковая память.
- [x] Использовать реальные наборы: 100 тысяч небольших файлов, несколько
  крупных файлов, смешанный проект, ZIP, solid 7Z, шифрованный архив и TAR.ZST.
  Хранить генераторы/манифесты, версии и хеши бинарников, медианы минимум 3 запусков.
- [x] Добавить чтение выбранного элемента для ZIP, где это допускает формат;
  проверять его CRC/размер, метаданные и текущие ограничения безопасности.
  Полное тестирование архива остаётся отдельной операцией. Для solid 7Z честно
  учитывать необходимость декодирования связанного блока.
- [x] Сократить повторные обходы и пересоздание модели при навигации/поиске;
  тяжёлую обработку метаданных вынести из потока интерфейса.
- [x] Распространить режимы ресурсов и явные настройки сжатия на пересборку
  ZIP/7Z; исправить расчёт прогресса при удалении элементов.
- [x] Проверить циклы открыть/закрыть/просмотреть/извлечь, чтобы находить
  накопление памяти и незакрытые файловые дескрипторы.

**Измеримые цели, которые нужно подтвердить базой:**

| Метрика | Критерий на зафиксированной машине и наборах |
| --- | --- |
| Интерфейс на 100 тысячах элементов | Фильтрация после ввода — до 200 мс в 95% измерений; длительная подготовка работает асинхронно |
| Выборочный просмотр в ZIP | Для небольшого выбранного файла не декодируются посторонние payload; измерение подтверждает выигрыш на соответствующем наборе |
| Отмена | Цель — до 1 секунды в поддерживаемых потоковых сценариях; неотменяемые участки декодеров измеряются и указываются отдельно |
| Регрессии | Ухудшение медианы времени более 10% или пикового RSS более 15% требует расследования и обоснования перед приёмкой |
| Повторные действия | После 100 циклов нет монотонного роста дескрипторов/удерживаемых сессий; рост памяти проверяется относительно прогретой базы |

Это цели приёмки на описанной конфигурации, а не обещания для любого компьютера.
Нарушение порога нельзя закрыть одним более удачным повторным запуском.

### E. Завершённый интерфейс и управление данными — P0

- [x] Сделать состояния вкладок, очереди и редактирования различимыми; показывать
  итог операции и доступное следующее действие без лишних модальных окон.
- [x] Добавить страницу временных файлов: занятое место, расположение, просмотр
  списка, удаление доступных копий. Заблокированные и несохранённые файлы
  объясняются отдельно; никаких обещаний физического стирания данных.
- [x] Довести управление клавиатурой, фокус, подписи для средств доступности,
  сохранение размеров/колонок и видимые команды узкого окна.
- [x] Проверить светлую/тёмную темы, EN/UK/RU, масштабы 100/125/150/200% и
  минимальный размер окна с Qt scale. Смена системного DPI Windows отдельно
  не квалифицирована и не выдаётся за результат Qt scale.
- [x] Оставить один актуальный статус возможностей и ссылаться на него;
  старые отчёты пометить как исторические. Устранить устаревшие описания
  предпросмотра, форматов и настроек в ARCHITECTURE/UI_DESIGN и других документах.

**Готово, когда:** пользователь видит несохранённую правку, понимает результат
пакета, может найти ошибку и освободить временные копии. Основные сценарии
доступны с клавиатуры; на проверенной матрице нет обрезанных критичных кнопок.

| 2. Отделить управление операциями | ArchiveSession, контроллер заданий, явные состояния | Этап 1 |
| 3. Завершить рабочее пространство | Вкладки, независимая навигация и корректное завершение заданий | Этап 2 |
| 4. Завершить очередь | Журнал, восстановление, повтор, пакетный итог | Этапы 2–3 |
| 5. Завершить редактирование | Замена содержимого в ядре, рабочие копии, конфликты, сохранение/восстановление | Этапы 2–4 |
| 6. Довести скорость и интерфейс | Выборочное чтение ZIP, пересборка, замеры, временные файлы, локализация | База этапа 1; итоговая проверка после этапа 5 |
| 7. Собрать кандидата 0.5 | Проверенные portable/installer, документация, отчёт | Все обязательные сценарии |

Каждый этап заканчивается работающим сценарием и проверкой. Не начинать
следующий большой слой поверх незавершённых состояний предыдущего.
Версия в коде переведена на 0.5.0 при подготовке проверяемого кандидата.

## Что не включать в обязательный объём 0.5

- Облачную синхронизацию, аккаунты, AI-функции и серверную инфраструктуру.
- Массовое добавление форматов, создание RAR, ISO/WIM/CAB.
- Запуск исполняемого содержимого и бесконтрольное сохранение правок.
- Встроенный браузер/Office-движок и большой набор новых декодеров документов.
- Одновременную запись нескольких заданий в один архив.
- Собственный механизм сетевого автообновления до решения вопроса доверия
  к подписи и проверке обновлений.

Эти направления можно пересмотреть после закрытия основных сценариев 0.5.
Подпись и проверка распространения учитываются отдельным релизным направлением.
Hyper-V не является зависимостью разработки этой версии; результаты непроведённых
проверок среды не подменяются локальными тестами.
